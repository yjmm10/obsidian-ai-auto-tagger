## 生成成功弹窗 + 空标签修复
- **需求1：生成完成后弹窗提示成功**
  - 问题：auto 模式（自动触发）`notice` 参数为 `mode !== "auto"` → `false`，不显示任何通知（包括成功）。用户看不到自动打标是否完成。
  - 修复：`main.ts` 的 `notice` 参数从 `mode !== "auto"` 改为 `mode !== "batch"`（auto 模式也显示通知，batch 不显示逐文件通知）。`tagger.ts` 成功通知条件从 `if (notice)` 改为 `if (mode !== "batch")`。
  - 效果：auto 模式成功时显示「🏷️ 已自动更新 {path}」；manual 显示「✅ 已写入 {path}」；batch 不显示逐文件通知（已有汇总 Notice）。
  - auto 模式的「内容不足」「无新增字段」提示仍被 `mode !== "auto"` 保护不显示（避免频繁打扰），但 API 调用失败会显示。

- **需求2：空标签不能算是有标签**
  - 问题：`isEmptyValue` 的 array 分支仅检查 `v.length === 0`，`[""]`、`["  "]` 等全空元素数组被视为「非空」（有标签），skip 策略下不会补全。
  - 修复：`field-apply.ts` 的 `isEmptyValue` array 分支增加 `v.every(item => String(item).trim() === "")` 全空检测。
  - 效果：`tags: [""]`、`tags: ["  ", ""]` 等视为空，skip 策略下会实时补全。
  - 新增 7 个测试用例（isEmptyValue 边界 + applyFields skip 策略），测试 95/0 通过。

- 验证：`npm run build` tsc+esbuild 通过，`npm test` 95/0，已部署 main.js 到测试库 v1.7.0。

## AI 请求超时错误提示优化
- **问题**：用户截图显示报错 `AI Tagger: 调用失败 - 连接/超时失败：signal is aborted without reason`。`timeoutSignal` 使用 `ctrl.abort()` 未传 reason，底层只能抛出 `signal is aborted without reason`；`describeError` 又将含 `abort` 的消息统一归类为「连接/超时失败」，用户无法判断是超时、网络故障还是请求被取消。
- **修复**（`ai-client.ts`）：
  1. `timeoutSignal` 在 `abort()` 时传入 `new Error("请求超时（${realMs} 毫秒）")`，让错误信息明确指向超时。
  2. `describeError` 按优先级区分：含 `timeout` → `请求超时：...`；含 `abort` → `请求已取消：...`；含 `ECONN/fetch/network` → `连接失败：...`。
- **效果**：超时场景会显示 `AI Tagger: 调用失败 - 请求超时：请求超时（30000 毫秒）`，便于用户排查网络/模型响应慢或调整设置中的「请求超时（毫秒）」。
- 验证：`npm run build` 通过，`npm test` 95/0，已部署 main.js 到测试库。

## predefined 模式严格过滤导致字段不生效（修复）
- **根因**：用户 `tags` 和 `summary` 字段配置为 `predefined` 模式。标签池来自 vault 扫描（`tagSource: "both"`），整个 vault 仅 `测试使用.md` 有 5 个 Obsidian 相关标签。AI 根据笔记内容生成的标签（如 `Python`、`调试`）一个都不在池里 → `filterAllowed(strict=true)` 全部过滤掉 → 空数组 → `coerceFields` 不写入 → `applyFields` 因 `!(key in aiData)` 跳过 → **字段不生效**。`summary` 字符串字段同理（strict 模式未命中 → `val = ""` → 不写入）。
- **修复**（`ai-client.ts`）：
  1. `filterAllowed`：全部越界时保留原值（去掉 `&& !strict` 条件），即使 predefined 严格模式也不清空。
  2. `coerceFields` 字符串 strict 分支：未命中时保留原值（`if (found) val = found` 替代 `val = found ?? ""`），不清空。
- **测试更新**：3 个用例从「不写入」改为「保留原值(安全降级)」，测试 95/0 通过。
- **用户配置注意**：`summary` 设为 predefined 模式不合理（摘要不是标签选择），但修复后安全降级不影响使用。`category` 无 mode 字段（undefined → generate 模式），正常工作。
